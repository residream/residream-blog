## 拷贝和赋值

### 对象的拷贝

**对象拷贝**是指：根据一个已经存在的对象，创建一个内容相同的**新对象**。

这里的重点是“新对象”。如果目标对象在这条语句执行前还不存在，就需要通过**拷贝构造函数**把它创建出来。

> 判断拷贝构造还是赋值，不看有没有 `=`，只看左侧目标对象在这条语句之前是否已经存在。

```cpp
class A {
    // 略
};

A a1;
A a2(a1);  // 根据 a1 创建新对象 a2：拷贝构造
A a3 = a1; // 根据 a1 创建新对象 a3：也是拷贝构造
```

对象拷贝并不等于“把内存里的数据随便复制一下”。对于普通成员，它可能表现为直接复制；但对于对象成员，仍然要遵从该成员所属类的拷贝规则。类中若管理动态内存、文件句柄等资源，拷贝方式尤其需要由程序员认真设计。

**对象为什么需要拷贝**：最典型的场景是按值传参和按值返回。

按值传参时，形参是函数栈帧中的一个新对象，而不是实参对象本身：

```cpp
class A {
    // 略
};

void function(A a) {
    // a 是由实参复制得到的新对象
}

int main() {
    A obj;
    function(obj); // 可能调用拷贝构造函数
}
```

按值返回对象时，调用者也需要得到一个独立的返回值对象。函数内的局部变量 `a` 位于本次函数调用的栈帧中，函数结束后它的生命周期就结束了，不能把它本身直接交给调用者继续使用：

```cpp
class A {
public:
    void g() const;
};

A function() {
    A a;
    return a;
}

int main() {
    function().g();
}
```

从学习和语义上看，以上两类情况都涉及“根据已有对象生成返回对象”的过程，因此是拷贝构造函数的典型使用场景。不过现代编译器通常会进行**返回值优化**（Return Value Optimization，RVO）或复制消除，实际运行时未必真的产生一次拷贝。不要把“某次运行没有看到拷贝构造函数被调用”误认为这种场景与拷贝构造无关。

例如可以直接返回匿名对象：

```cpp
A function() {
    return A(2);
}
```

编译器往往能够直接在返回值所需的位置构造对象。

### 拷贝构造函数

**拷贝构造函数**是构造函数的一种特殊形式，它的任务是：根据一个已有的同类对象，从无到有地构造一个新的同类对象。

典型声明为：

```cpp
class T {
public:
    T(const T& rhs);
};
```

它仍然具有构造函数的基本特征：

- 函数名与类名相同。
- 没有返回值类型。
- 可以是 `public`、`protected` 或 `private`。
- 第一个参数必须是本类对象的引用，课程中的常见形式只带这一个参数。

常见的形参类型是 `const T&`：

```cpp
T(const T& rhs);
```

其中：

- `T&` 表示按引用传递，避免为了传递形参而再次复制一个 `T` 对象。
- `const` 表示把 `rhs` 当作拷贝样本，不应在拷贝过程中修改它。

**为什么不能按值传递**：若写成下面这样：

```cpp
T(T rhs); // 错误的设计
```

为了给 `rhs` 传值，编译器又需要先调用拷贝构造函数；而调用拷贝构造函数又要传 `rhs`，会形成无法结束的递归。因此拷贝构造函数的参数必须以引用形式接收本类对象。

拷贝构造函数也可以写成：

```cpp
T(T& rhs);
```

但这种写法不能从 `const T` 对象拷贝，适用范围较窄。除非确实需要在拷贝过程中修改源对象，否则应优先使用 `const T&`。

> C++11 引入的 `T(T&& rhs)` 是**移动构造函数**，它用于接管右值对象的资源，与通常的拷贝构造函数 `T(const T& rhs)` 不同。

**拷贝构造和赋值的区别**：判断关键只有一个——左侧目标对象在这条语句之前是否已经存在。

```cpp
A a1;
A a2;
a1 = a2; // 赋值：a1 在这条语句之前已经存在

B b1;
B b2(b1);  // 拷贝构造：b2 在这条语句之前不存在
B b3 = b1; // 拷贝构造：b3 在这条语句之前不存在
```

`=` 的出现并不能说明一定是赋值。声明并初始化中的 `B b3 = b1;` 本质仍是创建 `b3`，因此是拷贝构造。

由于类型A的未知，这里前者的 `=` 实际需要用到运算符重载，即调用：

```cpp
A& operator=(const A& rhs);
```

这里可以正常运行，因为编译器会自动生成一个类似这样的赋值运算符：

```cpp
A& operator=(const A& rhs) {
    this->x = rhs.x;
    return *this;
}
```

所以这句：

```cpp
a1 = a2;
```

调用的是：

```cpp
a1.operator=(a2);
```

后者的 `=` 则是因为 `b3` 在这条语句之前还不存在，所以是在创建 `b3`，调用的是拷贝构造函数：

```cpp
B(const B& rhs);
```

等价理解为：

```cpp
B b3(b1);
```

可以把二者放在一起比较：

| 对比项       | 拷贝构造                     | 对象赋值                     |
| ------------ | ---------------------------- | ---------------------------- |
| 左侧对象     | 当前语句中刚创建，之前不存在 | 语句执行前已经存在           |
| 典型写法     | `B b2(b1);`、`B b3 = b1;`    | `b2 = b1;`                   |
| 对应成员函数 | `B(const B& rhs)`            | `B& operator=(const B& rhs)` |
| 主要任务     | 为新对象建立初始状态         | 改写已有对象的状态           |

对于自定义类型，推荐把拷贝构造写成括号形式：

```cpp
B b2(b1);
```

这样更容易一眼看出它是在构造新对象。内置类型则通常保留传统初始化写法：

```cpp
int x = 10;
double y = 3.14;
```

**成员对象会触发其拷贝构造函数**。例如：

```cpp
class A {
public:
    A(int n);
    A(const A& rhs);
};

class B {
public:
    B(A& a) : a_(a) {} // 用 a 构造成员 a_，调用 A 的拷贝构造函数
    B(int n) : a_(n) {} // 用 n 构造成员 a_，调用 A(int)

private:
    A a_;
};
```

成员 `a_` 是一个 `A` 对象。构造 `B` 时，`a_` 必须先被构造；传入 `A` 对象时会使用 `A` 的拷贝构造函数，传入 `int` 时则匹配 `A(int)`。

### 缺省拷贝构造函数

如果用户没有显式声明拷贝构造函数，编译器通常会为类隐式声明一个**缺省拷贝构造函数**。

```cpp
class A {
public:
    int value_;
};

A a1;
A a2(a1); // 使用编译器提供的缺省拷贝构造函数
```

课程中可把它理解为类似下面的效果：

```cpp
class A {
public:
    A(const A& rhs) {
        value_ = rhs.value_;
    }

private:
    int value_;
};
```

实际由编译器生成的函数会按照每个成员的类型分别处理，并不一定就是上面这一段代码。但它的核心特点是：编译器只会按成员的既有规则复制，不会自动理解“这块资源应该由谁拥有”。

这点与**缺省构造函数**不同：类中只要声明了任意构造函数，编译器通常就不再自动补无参构造函数；但只是声明普通的有参构造函数，并不会自动让类失去缺省拷贝构造能力。只有当用户自己声明拷贝构造函数，或类成员本身不可拷贝等条件出现时，才需要按对应规则处理。

缺省拷贝构造函数通常是 `public` 的。若某些成员本身不能复制，或者其可访问性不允许复制，隐式生成的拷贝构造函数也可能被定义为删除，导致对象不能拷贝。

**缺省拷贝构造函数通常执行浅拷贝**。这并不是说它真的把整个对象机械地按字节复制到新地址，而是说它不会额外复制指针所指向的资源。下一节会具体说明。

### 浅拷贝

**浅拷贝**（也常被称为位拷贝、浅复制）可以粗略理解为：复制对象自身保存的成员值，而不继续复制指针指向的堆区资源。

考虑下面这个类：

```cpp
class AA {
    // 略
};

class My {
public:
    My(AA& a) : ref_aa_(a) {}

private:
    int value_;
    AA* p_aa_;
    AA& ref_aa_;
    AA aa_;
};
```

如果用缺省拷贝构造函数构造 `m2`：

```cpp
My m1(a);
My m2(m1);
```

各类成员的大致处理方式如下：

- **静态数据成员**不属于某个对象自身，拷贝对象时不会复制它。所有对象本来就共享同一个静态成员。
- **内置类型成员**，如 `int value_`，直接复制其数值。
- **指针成员**，如 `AA* p_aa_`，直接复制指针中保存的地址值。
- **引用成员**，如 `AA& ref_aa_`，会让新对象中的引用仍然绑定到原对象引用的同一个 `AA` 对象；引用不能在初始化后重新绑定。
- **对象成员**，如 `AA aa_`，会调用 `AA` 的拷贝构造函数来构造新成员对象。

因此，浅拷贝中的“浅”尤其体现在指针成员上：

```cpp
m2.p_aa_ == m1.p_aa_;
```

两个指针变量位于不同的对象中，但其中保存的是相同地址，所以它们指向同一块堆区资源。

**浅拷贝的不足**：如果类拥有指针所指向的资源，并在析构函数中负责释放该资源，浅拷贝极易产生重复释放。

```cpp
class A {
    // 略
};

class B {
public:
    B() {
        p_a_ = new A;
    }

    ~B() {
        delete p_a_;
    }

private:
    A* p_a_;
};

int main() {
    B b1;
    B b2(b1); // 使用缺省拷贝构造函数，浅拷贝 p_a_
}
```

执行 `B b2(b1);` 后，内存关系可以理解为：

```text
b1.p_a_ ──┐
          ├── 同一块堆区 A 对象
b2.p_a_ ──┘
```

作用域结束时，局部对象按创建的相反顺序析构：

1. `b2` 的析构函数执行，释放 `p_a_` 指向的 `A` 对象。
2. `b1` 的析构函数执行，又对同一地址执行 `delete`。

第二次 `delete` 属于未定义行为，常见表现是程序崩溃或运行时错误。

浅拷贝本身不是错误。一个类若不拥有资源，只是借用外部对象，复制指针地址可能恰好就是正确语义。问题在于：**不能让两个对象都以“唯一拥有者”的身份释放同一块资源。**

### 使用自定义拷贝构造函数

当缺省拷贝构造函数的浅拷贝不符合类的语义时，就需要编写**自定义拷贝构造函数**。

最常见的目的，是让新对象获得一份独立的资源，即实现**深拷贝**。

仍以管理堆区 `A` 对象的 `B` 类为例：

```cpp
class B {
public:
    B() : p_a_(new A) {}

    B(const B& rhs)
        : p_a_(new A(*rhs.p_a_)) {}

    ~B() {
        delete p_a_;
    }

private:
    A* p_a_;
};
```

`new A(*rhs.p_a_)` 的含义是：根据右侧对象所拥有的 `A` 对象，构造一个新的 `A` 对象，并把新地址交给当前对象的 `p_a_`。

此时：

```text
b1.p_a_ ──────> 堆区 A 对象 1
b2.p_a_ ──────> 堆区 A 对象 2
```

两块 `A` 对象内容相同、地址不同；`b1` 和 `b2` 各自拥有自己的资源，析构时分别释放，因此不会重复 `delete`。这就是深拷贝。

也可以在构造函数体中完成分配：

```cpp
B::B(const B& rhs) {
    p_a_ = new A(*rhs.p_a_);
}
```

对于指针成员，这种写法可以工作；但初始化列表通常更清楚地表达“成员在对象创建时就完成初始化”。

**构造函数的初始化规则仍然有效**。若类含有引用成员、`const` 成员，或没有默认构造函数的对象成员，它们通常必须通过初始化列表处理：

```cpp
class B {
public:
    B(const B& rhs)
        : p_a_(new A(*rhs.p_a_)),
          ref_a_(rhs.ref_a_),
          a_(rhs.a_) {}

private:
    A* p_a_;
    A& ref_a_;
    A a_;
};
```

其中 `ref_a_` 只能在初始化阶段绑定；`a_(rhs.a_)` 会调用 `A` 的拷贝构造函数。

**哪些情况需要自定义拷贝构造函数**：

- 类需要深拷贝，例如对象独占管理动态内存、文件句柄或其他资源。
- 类希望按业务规则定制拷贝行为，例如记录拷贝次数或复制后生成新的编号。
- 类根本不应该被复制，例如互斥量、某些单例管理对象或独占资源对象。

**禁止拷贝的旧式写法**：把拷贝构造函数声明为私有且不提供实现。

```cpp
class My {
public:
    My() = default;

private:
    My(const My& rhs); // 只声明，不实现
};
```

类外代码尝试拷贝：

```cpp
My obj1;
My obj2(obj1); // 编译错误：私有成员不可访问
```

因为用户已经声明过拷贝构造函数，编译器不会再生成可用的缺省拷贝构造函数。

“私有但有实现”和“私有且无实现”有区别：

```cpp
class My {
public:
    My() = default;

private:
    My(const My& rhs) {
        // 略
    }

    void f() {
        My m1;
        My m2(m1); // 类内部可以访问私有拷贝构造函数
    }
};
```

私有函数仍可在本类内部使用；若真的要阻止任何地方调用，旧式做法应当不提供实现。此时本类内部一旦实际调用该函数，通常会在链接阶段报“找不到定义”。

另一种不推荐的写法是把拷贝构造函数声明为 `public`，但不提供类外实现：

```cpp
class My {
public:
    My() = default;
    My(const My& rhs); // 没有实现
};
```

这种代码可能通过编译，却在链接时因找不到函数定义而失败。与其让错误拖到链接阶段，不如尽量在编译阶段就阻止错误调用。

**C++11 及以后推荐使用 `= delete`**：

```cpp
class My {
public:
    My() = default;
    My(const My& rhs) = delete;
};
```

它明确表示该函数不能使用，任何拷贝行为都会直接在编译期报错。

禁止拷贝不只影响 `My b(a);`，还会影响按值传参和按值返回：

```cpp
void wrong(My obj); // 调用时需要拷贝构造

My make(); // 某些语境下也需要可访问的拷贝或移动构造
```

不能复制的对象通常应通过引用或指针传递，例如 `void f(const My& obj);`。

### 对象的赋值

**对象赋值**是指：左右两个对象都已经存在时，用右侧对象的状态修改左侧对象。

```cpp
int main() {
    A a1;
    A a2(a1);  // 拷贝构造：a2 原来不存在
    A a3 = a2; // 拷贝构造：a3 原来不存在

    a3 = a1;   // 对象赋值：a3 原来已经存在
}
```

一句话区分：

- **拷贝构造**解决“怎样创建一个新对象”。
- **对象赋值**解决“怎样修改一个已有对象”。

对象赋值对应的成员函数叫做**赋值函数**，更准确地说是**拷贝赋值运算符**。它重载的是 `=` 运算符。

如果用户没有自定义赋值函数，编译器通常会提供缺省赋值函数。例如：

```cpp
class A {
public:
    int value_;
};

A a1;
A a2;
a2 = a1; // 使用缺省赋值函数
```

缺省赋值函数通常是 `public` 的，并逐个对非静态数据成员执行赋值。它的效果与浅拷贝类似，因此常被称为**浅赋值**。

不同成员在浅赋值中的大致表现：

- 内置类型成员复制数值。
- 指针成员复制地址值。
- 对象成员调用其所属类的赋值函数。
- 静态数据成员不属于某个对象，不是对象赋值的对象状态。
- 引用成员不能重新绑定，因此含非静态引用成员的类通常不能使用隐式生成的拷贝赋值运算符。

例如：

```cpp
class AA {
    // 略
};

class My {
public:
    My(AA& ra) : ref_aa_(ra) {}

private:
    int value_;
    AA* p_aa_;
    AA& ref_aa_;
    AA aa_;
};

int main() {
    AA a1;
    AA a2;
    My m1(a1);
    My m2(a2);

    m1 = m2; // 通常错误：引用成员不能被重新绑定
}
```

`m1 = m2` 若想让 `m1.ref_aa_` 改为引用 `a2`，就需要把一个已绑定的引用重新绑定；这是 C++ 不允许的。因此，含非静态引用成员的类，其隐式拷贝赋值运算符会被定义为删除。

这不等于“含引用成员的类绝对不能写赋值函数”。程序员仍可自定义 `operator=`，例如让 `ref_aa_ = rhs.ref_aa_` 去给**被引用的 `AA` 对象赋值**；但这修改的是被引用对象的内容，并不是让 `ref_aa_` 改绑到另一个对象。这样的语义是否合理，要由类的设计目的决定。

**浅赋值的不足**：对拥有动态资源的类，浅赋值比浅拷贝多一个典型问题——它会先丢失左侧对象原来的资源。

```cpp
class A {
    // 略
};

class B {
public:
    B() : p_a_(new A) {}

    ~B() {
        delete p_a_;
    }

private:
    A* p_a_;
};

int main() {
    B b1;
    B b2;
    b1 = b2; // 使用缺省赋值函数，浅赋值 p_a_
}
```

赋值前，`b1`、`b2` 各自拥有一块堆区 `A` 对象。浅赋值的核心效果类似：

```cpp
b1.p_a_ = b2.p_a_;
```

这会带来两个问题：

1. **内存泄漏**：`b1` 原来持有的地址被覆盖，却没有先 `delete`；原来的那块堆区对象失去了所有可访问它的指针。
2. **重复释放**：赋值后 `b1.p_a_` 与 `b2.p_a_` 指向同一资源。两个 `B` 对象析构时都执行 `delete p_a_`，同一资源会被释放两次。

因此，类一旦拥有资源，就不能只写构造和析构；还必须审视对象赋值时应该如何处理旧资源与新资源。

### 自定义赋值函数

当缺省赋值函数的浅赋值不满足要求时，需要定义自己的赋值函数。典型声明如下：

```cpp
class T {
public:
    T& operator=(const T& rhs);
};
```

这行代码可分为三部分：

| 部分           | 含义                  |
| -------------- | --------------------- |
| `T&`           | 返回当前对象的引用    |
| `operator=`    | 对 `=` 运算符的函数名 |
| `const T& rhs` | 右侧的源对象          |

对于表达式：

```cpp
left = right;
```

在成员函数形式中：

- `rhs` 表示右侧的 `right`。
- `this` 指针隐含地表示左侧的 `left`。
- `*this` 表示左侧的当前对象本身。

**参数通常写成 `const T&`**：

```cpp
T& operator=(const T& rhs);
```

- `const` 保证不会在赋值过程中修改右侧对象。
- `&` 避免按值传参时额外调用拷贝构造函数。

**为什么返回 `T&`**：赋值表达式本身也有结果。内置类型支持链式赋值：

```cpp
int a;
int b;
int c;

a = b = c;
```

它可以理解为：

```cpp
a = (b = c);
```

为了让自定义对象也保持这种行为，赋值函数应返回当前对象的引用：

```cpp
T& T::operator=(const T& rhs) {
    // 完成赋值
    return *this;
}
```

若返回 `void`：

```cpp
void operator=(const T& rhs);
```

则 `b = c` 没有可继续使用的结果，`a = b = c` 无法按正常语义成立。

若返回 `T`：

```cpp
T operator=(const T& rhs);
```

虽然部分链式表达式可能可以编译，但会额外生成临时对象。例如 `(a = b) = c` 更可能修改临时对象，而不是 `a` 本身，既低效也不符合内置赋值运算符的习惯。

> `this` 是指针，类型为 `T*`；`*this` 才是当前对象，类型为 `T`。因此赋值函数通常返回 `*this`，而不是 `this`。

**深赋值的基础写法**：对于管理单个动态资源的类，可以这样定义：

```cpp
class B {
public:
    B() : pch_(new char('\0')) {}

    B(const B& rhs) : pch_(new char(*rhs.pch_)) {}

    ~B() {
        delete pch_;
    }

    B& operator=(const B& rhs) {
        if (this != &rhs) {
            delete pch_;
            pch_ = new char(*rhs.pch_);
        }
        return *this;
    }

private:
    char* pch_;
};
```

这段代码体现了自定义赋值函数的四个关键步骤：

1. 判断是否自我赋值。
2. 释放当前对象原有的资源。
3. 根据右侧对象申请并复制新的独立资源。
4. 返回 `*this`，支持链式赋值。

**为什么必须检查自我赋值**：最直接的自我赋值是：

```cpp
B b1;
b1 = b1;
```

更隐蔽的情况是别名：

```cpp
B b1;
B& b2 = b1;

b1 = b2;
```

虽然左、右两边变量名不同，但 `b2` 只是 `b1` 的引用；它们代表同一个对象。

若没有自我赋值判断，下面的顺序会出错：

```cpp
delete pch_;
pch_ = new char(*rhs.pch_);
```

当 `rhs` 与当前对象是同一个对象时，第一行释放的不只是当前对象的资源，也正是 `rhs.pch_` 指向的资源；第二行随后读取已释放内存，形成未定义行为。

因此要比较对象地址：

```cpp
if (this != &rhs) {
    // 只有左右对象不是同一个对象时，才执行资源替换
}
```

比较变量名没有意义，比较地址才能识别引用等别名带来的自我赋值。

上面的课程基础版本能避免自我赋值、内存泄漏和重复释放。但若 `new` 分配失败，旧资源已经被 `delete`，当前对象可能被破坏。更稳妥的写法是先准备好新资源，再替换旧资源：

```cpp
B& B::operator=(const B& rhs) {
    if (this != &rhs) {
        char* new_pch = new char(*rhs.pch_);
        delete pch_;
        pch_ = new_pch;
    }
    return *this;
}
```

此时若 `new` 抛出异常，`pch_` 还没有被删除，当前对象仍保持赋值前的有效状态。

对于资源管理类，拷贝构造、拷贝赋值和析构函数往往需要一起考虑：

```cpp
class B {
public:
    B();
    B(const B& rhs);             // 深拷贝
    B& operator=(const B& rhs);  // 深赋值
    ~B();                        // 释放资源
};
```

这就是经典的**三法则**（Rule of Three）：若类需要自定义析构函数、拷贝构造函数或拷贝赋值运算符中的任意一个，通常也需要审查另外两个是否必须自定义。

在现代 C++ 中，若类直接管理资源，还应进一步考虑移动构造函数与移动赋值运算符（五法则）；更理想的情况是把资源交给 `std::string`、`std::vector`、智能指针等 RAII 类型管理，使类不必手写这些特殊成员函数（零法则）。本章首先要牢固掌握的仍是：**新对象用拷贝构造，旧对象改值用赋值；管理资源时，浅拷贝与浅赋值往往不够。**

## 运算符重载

### 运算符的重载

**运算符重载**是指：为 C++ 已有的运算符提供一份适用于自定义类型的函数定义，使自定义对象也能使用接近内置类型的表达式写法。

例如，二维向量相加可以写成普通成员函数：

```cpp
class TVector {
public:
    TVector(int x, int y) : x_(x), y_(y) {}

    TVector addVector(const TVector& rhs) const {
        return TVector(x_ + rhs.x_, y_ + rhs.y_);
    }

private:
    int x_;
    int y_;
};

TVector v1(1, 2);
TVector v2(3, 4);
TVector result = v1.addVector(v2);
```

上面的写法没有错，但向量相加本身有很强的数学含义。若能写成：

```cpp
TVector result = v1 + v2;
```

读代码的人不需要先查 `addVector` 的具体名字，就能大致理解这是“两个向量相加”。这就是运算符重载的意义：用已有符号表达符合直觉的对象操作。

普通自由函数也可以完成相同工作：

```cpp
TVector addVector(const TVector& lhs, const TVector& rhs);
```

但函数名可以被不同程序员写成 `addVector`、`add`、`plus` 等；而 `+` 的通常含义比较稳定。运算符重载并没有让程序“更能做事”，它主要让接口更自然、更接近对象所代表的领域概念。

> 运算符重载不是创造新运算符，而是给已有运算符赋予适合自定义类型的含义。

**运算符的分类**：按操作数个数，课程中常把运算符分为三类：

- **一元运算符**：只有一个操作数，如正号 `+a`、负号 `-a`、`++a`、`a++`、`!a`、`~a`、`*p`、`&a`。
- **二元运算符**：有两个操作数，如 `a + b`、`a * b`、`a = b`、`a += b`、`a << b`。
- **三元运算符**：有三个部分参与，如条件运算符 `a > b ? a : b`。

运算符重载函数的函数名由关键字 `operator` 和运算符组成：

```text
operator+
operator=
operator[]
operator()
operator->
```

例如：

```cpp
TVector operator+(const TVector& lhs, const TVector& rhs);
```

这里 `operator+` 是函数名。它看起来像符号，本质仍然是一个函数。

**运算符重载的本质**：表达式最终会被编译器转换成相应的函数调用。

```cpp
a + b;
```

若 `+` 写成自由函数，可理解为：

```cpp
operator+(a, b);
```

若 `+` 写成成员函数，可理解为：

```cpp
a.operator+(b);
```

因此，运算符重载没有脱离函数调用规则；参数传递、返回值、访问控制、`const`、函数重载等知识依然全部适用。

**哪些运算符可以重载**：大多数现有 C++ 运算符都允许重载，例如：

```text
+  -  *  /  %  ^  &  |  ~
!  =  <  >  +=  -=  *=  /=  %=
^= &= |= << >> >>= <<=
== != <= >= && || ++ --
->* -> , [] ()
new delete new[] delete[]
```

其中 `new`、`delete`、`new[]`、`delete[]` 也可以重载；它们通常用于自定义内存分配与释放策略，后续动态内存管理章节会进一步讨论。

**不能重载的运算符或关键字**包括：

```text
.    .*    ::    ?:
sizeof    typeid
static_cast    dynamic_cast    const_cast    reinterpret_cast
```

特别要记住：`.`、`.*`、`::`、`?:` 不能重载。其中条件运算符 `?:` 是三元运算符，C++ 不能重载它。

**运算符重载的限制**：运算符重载不是任意修改 C++ 语法，它有明确边界。

1. **不能改变操作数个数** `+` 用作二元加法时有两个操作数，重载后仍然是二元操作；`++` 仍然是一元操作。后置 `++` 写成 `operator++(int)` 中的 `int` 只是区分前后置的语法标记，并没有把 `++` 变成真正的二元运算符。
2. **不能改变优先级和结合性**

   ```cpp
      a + b * c;
   ```

   无论 `+`、`*` 是否被重载，表达式仍按原有规则先计算 `b * c`，再计算加法。

   同样，`+` 仍然左结合：

   ```cpp
      a + b + c;
   ```

   成员函数形式可理解为：

   ```cpp
      a.operator+(b).operator+(c);
   ```

   而 `=` 仍然右结合：

   ```cpp
      a = b = c;
   ```

   可理解为：

   ```cpp
      a.operator=(b.operator=(c));
   ```

3. **不能发明新运算符** 不能先造出 `**`、`⊕`、`∩` 等符号，再为它们写 `operator**`。只能重载 C++ 已经定义的运算符。
4. **至少有一个操作数必须是自定义类型** 不能改变纯内置类型之间原有的运算规则：

   ```cpp
      int operator+(int lhs, int rhs); // 错误
   ```

   至少有一个操作数必须是类类型或枚举类型。也就是说，运算符重载服务于用户自定义类型，不能篡改 `int + int`、`double * double` 这类内置运算的含义。

5. **应保持常见语义** 语法上可以把 `+` 的实现写成减法，但这样会让读者产生错误理解。运算符重载的目的应当是减少理解成本，而不是制造谜语。

### 二元运算符重载

**二元运算符**有两个操作数，例如：

```cpp
v1 + v2;
```

`v1` 是左操作数，`v2` 是右操作数。二元运算符重载有两种常见形式：自由函数形式和成员函数形式。

**自由函数形式**：把左右两个操作数都写成显式参数。

```cpp
class TVector {
public:
    TVector(int x, int y) : x_(x), y_(y) {}

    int getX() const { return x_; }
    int getY() const { return y_; }

private:
    int x_;
    int y_;
};

TVector operator+(const TVector& lhs, const TVector& rhs) {
    return TVector(lhs.getX() + rhs.getX(),
                   lhs.getY() + rhs.getY());
}
```

表达式：

```cpp
v1 + v2;
```

可以理解为：

```cpp
operator+(v1, v2);
```

自由函数中两个操作数地位比较对称。对于 `+`、`-`、`*`、`/`、`==`、`<` 这类通常不修改操作数的普通二元运算，自由函数往往很自然。

如果自由函数确实需要访问类的私有成员，可以在类中声明它为**友元函数**：

```cpp
class A {
    friend A operator+(const A& lhs, const A& rhs);

public:
    A(int x, int y) : x_(x), y_(y) {}

private:
    int x_;
    int y_;
};

A operator+(const A& lhs, const A& rhs) {
    return A(lhs.x_ + rhs.x_, lhs.y_ + rhs.y_);
}
```

`operator+` 仍然不是 `A` 的成员函数，它没有隐含的 `this` 指针；`friend` 只赋予它访问私有成员的权限。

**成员函数形式**：左操作数由当前对象表示，右操作数作为显式参数传入。

```cpp
class TVector {
public:
    TVector(int x, int y) : x_(x), y_(y) {}

    TVector operator+(const TVector& rhs) const {
        return TVector(x_ + rhs.x_, y_ + rhs.y_);
    }

private:
    int x_;
    int y_;
};
```

表达式：

```cpp
v1 + v2;
```

可以理解为：

```cpp
v1.operator+(v2);
```

所以成员函数形式中：

- 左操作数 `v1` 由隐含的 `this` 指针表示；
- 参数列表中只写右操作数 `v2`；
- 左操作数必须是能够作为当前对象的自定义类型。

这也解释了成员函数形式的一个限制。若只写：

```cpp
class Complex {
public:
    Complex operator+(double rhs) const;
};
```

它可以支持：

```cpp
complex + 2.0;
```

但不能直接支持：

```cpp
2.0 + complex;
```

因为左操作数 `2.0` 是 `double`，不能写成 `2.0.operator+(complex)`。如果希望左右两种顺序都能自然使用，通常应把这类 `operator+` 写成自由函数。

**成员函数末尾的 `const`**：对于不修改对象的普通加法，常见声明为：

```cpp
TVector operator+(const TVector& rhs) const;
```

这里有两个 `const`，含义不同：

- `const TVector& rhs`：函数不修改右操作数。
- 函数末尾的 `const`：函数不修改左操作数，也就是不修改当前对象。

普通 `+` 应当产生新结果，而不应修改 `lhs` 或 `rhs`，所以成员版本通常需要在末尾加 `const`。

**返回类型应参考内置类型语义**：写运算符重载时，不能只关注“能不能编译”，还要看内置类型中相同运算的结果是什么。

| 表达式   | 常见返回类型 | 原因                       |
| -------- | ------------ | -------------------------- |
| `!a`     | `bool`       | 逻辑非得到真假结果         |
| `a * b`  | `T`          | 产生一个新的计算结果       |
| `a = b`  | `T&`         | 修改左侧对象，支持链式赋值 |
| `a *= b` | `T&`         | 修改左侧对象，返回当前对象 |

因此，普通加、减、乘、除通常按值返回新对象：

```cpp
TVector operator+(const TVector& lhs, const TVector& rhs);
```

而赋值、复合赋值等会修改左侧对象的运算，通常返回左侧对象的引用：

```cpp
TVector& operator+=(const TVector& rhs);
TVector& operator=(const TVector& rhs);
```

不要返回局部对象的引用：

```cpp
const TVector& badAdd(const TVector& lhs, const TVector& rhs) {
    TVector result(lhs.getX() + rhs.getX(), lhs.getY() + rhs.getY());
    return result; // 错误：result 离开函数后被销毁
}
```

普通 `+` 返回新对象的值是正确语义；现代编译器通常会进行**返回值优化**，无需为了担心一次副本而错误地返回局部对象引用。

### 成对重载

一些语义相关的运算符，通常应成对提供。最典型的是：

```text
+
+=
```

也就是普通加法 `+` 与加并赋值 `+=`。

```cpp
a = a + b;
a += b;
```

二者效果相近，但表达的意图不同：前者表示“计算和，再赋给 `a`”；后者直接表达“在 `a` 自身上加上 `b`”。内置类型同时支持这两种写法，自定义类型通常也应支持。

**`+=` 的语义**：`+=` 必须修改左侧对象，因此很适合写成成员函数：

```cpp
class A {
public:
    A(int x, int y) : x_(x), y_(y) {}

    A& operator+=(const A& rhs) {
        x_ += rhs.x_;
        y_ += rhs.y_;
        return *this;
    }

private:
    int x_;
    int y_;
};
```

`a += b` 可以理解为：

```cpp
a.operator+=(b);
```

函数末尾返回 `*this`，原因和赋值函数相同：

- `this` 是当前对象地址；
- `*this` 是当前对象本身；
- 返回 `A&` 可以让结果继续代表左侧对象。

例如：

```cpp
(a += b) += c;
```

第一次 `a += b` 返回 `a` 的引用，第二次仍然在同一个 `a` 对象上继续执行。

**`+` 的语义**：普通 `+` 不应修改两个原操作数，而是返回新的结果对象。

可以先实现 `+=`，再让 `+` 复用 `+=`：

```cpp
class A {
public:
    A(int x, int y) : x_(x), y_(y) {}

    A& operator+=(const A& rhs) {
        x_ += rhs.x_;
        y_ += rhs.y_;
        return *this;
    }

private:
    int x_;
    int y_;
};

A operator+(A lhs, const A& rhs) {
    lhs += rhs;
    return lhs;
}
```

这里 `lhs` 按值传递，因此它是左操作数的一个副本。`lhs += rhs` 修改的是副本而不是原来的左操作数，最后按值返回副本，正好符合 `+` 不修改原对象的语义。

这种实现方式还有两个好处：

1. 真正的“加并赋值”逻辑只维护在 `operator+=` 中，减少重复代码。
2. `operator+` 不必直接读取 `A` 的私有成员，因此不一定需要 `friend`。

当类增加新成员时，例如从二维坐标增加 `z_`，只要把 `operator+=` 的逻辑改完整，使用它实现的 `operator+` 会自动跟着正确工作。

类似的成对关系还有：

| 普通运算 | 复合赋值运算 |
| -------- | ------------ |
| `+`      | `+=`         |
| `-`      | `-=`         |
| `*`      | `*=`         |
| `/`      | `/=`         |
| `%`      | `%=`         |

成对重载的核心不是“为了凑数量”，而是让类型支持用户对内置类型已经形成的使用习惯。

### 一元运算符重载

**一元运算符**只有一个操作数。常见的一元运算符有正号、负号、逻辑非、按位取反、自增、自减等。本节重点理解前置 `++` 与后置 `++` 的重载。

对于内置 `int`：

```cpp
int a = 10;
++a;
a++;
```

两种写法都会让 `a` 加 `1`，但返回结果不同。

**前置自增 `++a`**：先修改，再返回修改后的对象。

可以粗略理解为：

```cpp
a += 1;
return a;
```

所以自定义类型的前置 `++` 通常写成：

```cpp
class A {
public:
    A& operator++() {
        ++num_;
        ++den_;
        return *this;
    }

private:
    int num_;
    int den_;
};
```

表达式：

```cpp
++a;
```

可理解为：

```cpp
a.operator++();
```

前置版本修改当前对象后，结果仍应代表当前对象，因此通常返回 `A&`。

**后置自增 `a++`**：先保存旧值，再修改当前对象，最后返回旧值。

可以粗略理解为：

```cpp
int temp = a;
a += 1;
return temp;
```

后置 `++` 与前置 `++` 使用同一个函数名 `operator++`。为了区分两者，C++ 规定后置版本额外带一个没有实际业务含义的 `int` 形参：

```cpp
class A {
public:
    A operator++(int) {
        A temp(*this);
        ++num_;
        ++den_;
        return temp;
    }

private:
    int num_;
    int den_;
};
```

表达式：

```cpp
a++;
```

可理解为：

```cpp
a.operator++(0);
```

这里的 `0` 由编译器用于区分语法，`int` 参数本身通常不会在函数体中使用，也不代表“自增多少”。

前、后置 `++` 的形式与返回类型要一起记：

| 写法  | 函数形式          | 返回含义           | 常见返回类型 |
| ----- | ----------------- | ------------------ | ------------ |
| `++a` | `operator++()`    | 自增后的当前对象   | `A&`         |
| `a++` | `operator++(int)` | 自增前保存的旧对象 | `A`          |

**分数类示例**：假设分数对象用 `num_ / den_` 表示，给分子加一个分母相当于让分数整体加 `1`。

```cpp
class Fraction {
public:
    Fraction(int num = 0, int den = 1) : num_(num), den_(den) {}

    Fraction& operator++() {
        num_ += den_;
        return *this;
    }

    Fraction operator++(int) {
        Fraction temp(*this);
        num_ += den_;
        return temp;
    }

private:
    int num_;
    int den_;
};
```

若 `a` 初始为 `1/3`：

```cpp
Fraction b = ++a;
```

执行后 `a` 和 `b` 都是 `4/3`，因为前置版本返回修改后的 `a`。

```cpp
Fraction c = a++;
```

`c` 得到自增前的旧值，而 `a` 自身仍会完成自增。这就是后置版本必须先保存副本、再按值返回副本的原因。

### 重载 []、()、-> 和流输入输出

有些运算符有很强的固定使用习惯。重载它们时，更要让行为接近数组、函数、指针或标准输入输出流的直觉。

**重载 `[]`**：下标运算符常用于让对象像数组一样访问内部元素。

```cpp
class A {
public:
    int operator[](int index) const {
        return nums_[index];
    }

    int& operator[](int index) {
        return nums_[index];
    }

private:
    int nums_[100];
};
```

使用时：

```cpp
A a1;
a1[0] = 10;

const A& a2 = a1;
int value = a2[0];
```

`[]` 常写成 `const` 与非 `const` 两个版本：

- `int operator[](int) const`：用于常对象，只读取元素，按值返回即可。
- `int& operator[](int)`：用于普通对象，返回元素引用，使 `a1[0] = 10` 能成立。

如果非 `const` 版本也只返回 `int`：

```cpp
int operator[](int index);
```

那么 `a1[0]` 得到的是一个临时值，不能作为可修改位置放到赋值号左侧。

课程示例为了突出语法通常省略下标检查。实际工程中，`operator[]` 往往保持数组风格而不检查范围；若需要带检查的访问，可以额外提供类似 `at()` 的成员函数。

> `operator[]` 必须是成员函数；常对象版本不能返回普通可修改引用，否则会破坏常对象不能被修改的语义。

**重载 `()`**：`()` 是函数调用运算符。重载后，对象可以像函数一样被调用。

```cpp
class A {
public:
    int operator()() const {
        return 999;
    }

    int operator()(int a, int b) const {
        return a + b;
    }
};
```

使用：

```cpp
A a;
int x = a();
int y = a(10, 30);
```

`operator()` 可以像普通函数一样拥有不同参数列表，因此可以重载多个版本。重载了 `operator()` 的对象常称为**函数对象**或**仿函数**。

函数对象常用于：比较器、排序规则、可配置策略对象，以及后续模板库和标准库算法中的回调行为。现代 C++ 中，很多一次性小行为也可以用 lambda 表达式表达；但函数对象仍然适合保存状态或复用复杂逻辑。

**重载 `->`**：箭头运算符用于让对象表现得像指针或指针代理。

```cpp
class A {
public:
    void f() {}
};

class B {
public:
    B(A* p) : p_a_(p) {}

    A* operator->() {
        return p_a_;
    }

private:
    A* p_a_;
};
```

使用：

```cpp
A a;
B b(&a);
b->f();
```

可理解为：

```cpp
(b.operator->())->f();
```

`operator->` 的返回值不能随便是一个普通对象。C++ 要求它的结果必须满足以下之一：

1. 返回指针类型；
2. 返回另一个自定义类型，且该类型还重载了 `operator->`。

因此可以形成代理链：

```cpp
c->f();
```

若 `c.operator->()` 返回对象 `b`，而 `b.operator->()` 再返回 `A*`，编译器会继续展开，直到得到真正可以执行 `->f()` 的指针。智能指针和代理对象常会使用这种机制。

**重载流输出 `<<`**：为了让对象能直接输出到 `cout`，通常写成非成员函数：

```cpp
#include <ostream>

class A {
public:
    int getX() const { return x_; }
    int getY() const { return y_; }

private:
    int x_ = 0;
    int y_ = 0;
};

std::ostream& operator<<(std::ostream& out, const A& obj) {
    out << obj.getX() << ' ' << obj.getY();
    return out;
}
```

使用：

```cpp
std::cout << obj << std::endl;
```

不能把它简单写成 `A` 的成员函数来实现 `cout << obj`，原因是成员函数形式中左操作数必须是当前对象：

```cpp
obj.operator<<(std::cout);
```

这对应的是 `obj << cout`，而不是我们希望的 `cout << obj`。`cout` 的类型是标准库的 `std::ostream`，我们不能去给标准库流类随意添加自己的成员函数，因此应让 `operator<<` 成为自由函数。

如果输出函数要直接读取 `A` 的私有成员，可以通过公有 getter，或把该自由函数声明为 `friend`。

**重载流输入 `>>`**：输入也通常写成非成员函数：

```cpp
#include <istream>

class A {
public:
    void setX(int x) { x_ = x; }
    void setY(int y) { y_ = y; }

private:
    int x_ = 0;
    int y_ = 0;
};

std::istream& operator>>(std::istream& in, A& obj) {
    int x;
    int y;
    in >> x >> y;
    obj.setX(x);
    obj.setY(y);
    return in;
}
```

第二个参数必须是普通 `A&`，不能写成 `const A&`，因为读取输入的目的就是修改对象。

`<<` 和 `>>` 都返回流对象的引用，才能支持连续输入输出：

```cpp
std::cout << a << b << std::endl;
std::cin >> a >> b;
```

可以理解为：第一次运算返回同一个流对象引用，后续运算继续以该流对象作为左操作数。

### 运算符重载的方针

运算符重载不只是语法题，更是类设计题。最重要的总原则是：**保持内置类型相同运算符的使用习惯和直觉语义。**

例如：

- `+` 应当产生新结果，而不是偷偷修改左操作数。
- `+=` 应当修改左操作数，并通常返回左操作数引用。
- `==` 应表达相等比较。
- `[]` 应表达元素访问。
- `a++` 应返回旧值，`++a` 应返回修改后的对象。
- 输出运算 `<<` 应返回输出流引用，方便继续输出。

若一个重载让读者无法凭运算符猜出大致含义，就不应使用运算符重载。

**成员函数还是非成员函数**：可以用下面的经验表整理。

| 运算符类型                  | 常见或要求的形式       | 原因                                   |
| --------------------------- | ---------------------- | -------------------------------------- |
| 所有一元运算符              | 成员函数（建议）       | 唯一操作数通常就是当前对象             |
| `=`、`[]`、`()`、`->`       | 非静态成员函数（必须） | C++ 对这四个运算符有语法要求           |
| `+=`、`-=`、`*=` 等复合赋值 | 成员函数（建议）       | 必然修改左操作数                       |
| 其他普通二元运算符          | 非成员函数（建议）     | 左右操作数更对称，也支持内置类型在左侧 |

这里要准确记住：标准 C++ 中必须写成非静态成员函数的是 `operator=`、`operator[]`、`operator()`、`operator->` 四个。

**一元运算符为什么建议成员函数**：一元运算符只有一个操作数，而这个操作数通常就是当前对象：

```cpp
++a;
```

成员形式最自然：

```cpp
a.operator++();
```

当然，部分一元运算符也可以写成自由函数；这里的“建议”是为了让代码结构更直观，不是所有一元运算符都被语言强制要求写成成员函数。

**复合赋值为什么建议成员函数**：

```cpp
a += b;
a -= b;
a *= b;
```

这些运算的共同点是左侧对象一定会被修改，因此成员函数中直接通过 `this` 操作左侧对象最符合语义：

```cpp
A& operator+=(const A& rhs);
```

**普通二元运算为什么常建议非成员函数**：对于：

```cpp
a + b;
a == b;
a < b;
```

自由函数可以把左右操作数都显式写出来，地位更对称。更重要的是，它能支持“自定义对象在右侧”的表达式：

```cpp
Complex operator+(double lhs, const Complex& rhs);
Complex operator+(const Complex& lhs, double rhs);
```

如果只提供成员函数版本，`complex + 2.0` 可能可用，但 `2.0 + complex` 往往无处去匹配。

**通常不要重载 `&&`、`||` 和 `,`**：

内置 `&&` 和 `||` 有短路求值特性：

```cpp
if (p != nullptr && p->valid()) {
}
```

当 `p == nullptr` 时，右侧 `p->valid()` 不会执行。可一旦重载 `operator&&` 或 `operator||`，它们会按普通函数调用处理，两个操作数都必须先完成求值，无法保持这种短路行为。

逗号运算符 `,` 也有固定的阅读与求值习惯，重载后容易让代码意图变得含糊。因此这三类运算符虽然能够重载，但通常不应重载。

最后可以把本章的判断思路浓缩成几句话：

1. 先问这个操作是否真的符合已有运算符的直觉含义。
2. 再看它是否修改左操作数，决定返回新值还是返回左侧引用。
3. 根据左操作数是否一定是自定义类型，选择成员或非成员形式。
4. 对 `=`、`[]`、`()`、`->`，直接写成非静态成员函数。
5. 不要为了“炫技”重载会破坏短路或阅读习惯的运算符。

运算符重载写得好，会让对象像 `int`、数组、指针或流一样自然；写得不好，则会让一行看似简单的表达式藏着反直觉的行为。它的核心从来不是少写几个字符，而是让类型的行为更清楚。

## 动态内存管理

### 存储空间

程序运行时，对象和数据并不都放在同一块内存中。为了理解动态内存管理，先把课程中常见的内存区域分清。

从课件的“五区”说法看，常见区域包括：代码区、常量数据区、变量数据区、栈区和堆区。复习动态内存管理时，最关心的是：普通局部对象通常随栈帧自动销毁；而通过 `new` 创建的对象位于动态存储区域，需要程序员决定何时释放。

| 区域            | 常见内容                                   | 生命周期或管理方式                              |
| --------------- | ------------------------------------------ | ----------------------------------------------- |
| 代码区          | 编译后的机器指令                           | 程序装入后可执行，通常只读                      |
| 常量数据区      | 字符串字面量、只读数据                     | 通常随程序存在                                  |
| 全局/静态数据区 | 全局变量、全局对象、静态变量、静态数据成员 | 通常从程序启动到结束                            |
| 栈区            | 函数形参、局部变量、局部自动对象、调用现场 | 进入作用域或函数调用时建立，离开时自动销毁      |
| 堆区/自由存储区 | `new` 创建的对象或数组                     | 运行到 `new` 时创建，通常运行到 `delete` 时释放 |

> 课件常把 `new` 得到的区域称为“堆区”或“自由存储区”。严格说，**自由存储区**是 C++ 语言层面的概念，**堆**是常见实现中的内存区域；在本章的常规理解中，可以把它们视为 `new/delete` 管理的动态内存区域。

**全局/静态数据区**常放全局变量、全局对象、静态变量和静态数据成员：

```cpp
int total = 88; // 全局变量

class A {
public:
    static int base;
};

int A::base = 5; // 静态数据成员的定义
```

它们不属于某一次函数调用的栈帧，生命周期通常贯穿整个程序运行过程。

局部静态变量虽然写在函数内部，也不在普通栈区：

```cpp
void f() {
    static int count = 0;
    ++count;
}
```

`count` 的**作用域**只在 `f` 的函数体内，但它的**生命周期**从第一次执行到声明处开始，一直持续到程序结束。不要把“写在函数里”和“存放在栈里”混为一谈。

**栈区**主要服务于函数调用。调用函数时，系统会建立一个栈帧；函数返回时，整个栈帧会自动销毁。普通局部变量、局部自动对象、形参和返回地址等通常都与栈帧有关：

```cpp
int add(int a, int b) {
    int result = a + b;
    return result;
}
```

这里每次调用 `add` 都会有自己的一份 `a`、`b` 和 `result`。递归调用时，每一层递归也都有独立栈帧：

```cpp
int sumTo(int n) {
    if (n == 0) {
        return 0;
    }

    int local = n;
    return local + sumTo(n - 1);
}
```

**堆区/自由存储区**用于动态创建对象：

```cpp
A* p = new A(10);
delete p;
```

`p` 如果是局部指针变量，它自己仍然在栈区；真正位于动态存储区的是 `p` 指向的 `A` 对象。这一点非常容易考：**指针变量的位置，和它指向对象的位置，可能完全不同。**

静态/自动管理和动态管理可以这样比较：

| 对比点     | 静态或自动管理                 | 动态管理                     |
| ---------- | ------------------------------ | ---------------------------- |
| 典型对象   | 全局对象、静态对象、局部对象   | `new` 创建的对象             |
| 创建时机   | 程序启动、进入作用域或函数调用 | 程序执行到 `new`             |
| 销毁时机   | 程序结束或离开作用域           | 程序执行到对应 `delete`      |
| 主要管理者 | 运行时机制                     | 程序员或资源管理对象         |
| 常见风险   | 栈空间有限、生命周期不够灵活   | 内存泄漏、重复释放、悬空指针 |

### 静态存储及其不足

静态存储和栈区自动管理的优点很明显：对象离开作用域时会自动析构，不需要程序员手写释放代码。

```cpp
void f() {
    A obj;
    // 使用 obj
} // 离开作用域，obj 自动析构
```

这种方式对小型、数量固定、生命周期与作用域一致的数据非常方便。但它也有几个明显限制。

**限制一：对象数量或数组大小可能在运行时才知道。**

```cpp
const int count = 50;
A objects[count];
```

标准 C++ 中，普通数组的大小需要是编译期常量表达式。若数组大小来自用户输入、文件内容或网络数据：

```cpp
int count;
std::cin >> count;
```

就不能用标准 C++ 的普通局部数组直接写成 `A objects[count];`。此时需要动态数组或更现代的 `std::vector`。

**限制二：对象生命周期与作用域绑定，不够灵活。**

```cpp
A makeA() {
    A obj;
    return obj;
}
```

局部对象 `obj` 会在函数结束时销毁。若某个对象必须在函数返回后仍然存在，并由调用方决定何时结束其生命周期，栈区局部对象就不能直接满足这个要求。

**限制三：栈空间有限。**

栈的分配和回收速度很快，但容量通常有限。局部定义很大的数组或进行过深递归，都可能导致栈溢出：

```cpp
void risky() {
    int values[10'000'000]; // 可能导致栈空间不足
}
```

**限制四：对象数组要求元素可默认构造。**

```cpp
class Card {
public:
    Card(int id);
};

Card cards[54]; // 错误：Card 没有无参构造函数
```

创建对象数组时，编译器需要逐个构造每个元素。若没有为每个元素提供参数，默认会尝试调用无参构造函数；而 `Card` 只有 `Card(int)`，因此数组无法构造。

可以用“指针数组 + 逐个动态创建”的方式绕过这一限制：

```cpp
class Poker {
public:
    Poker() {
        for (int i = 0; i < 54; ++i) {
            cards_[i] = new Card(i);
        }
    }

    ~Poker() {
        for (int i = 0; i < 54; ++i) {
            delete cards_[i];
        }
    }

private:
    Card* cards_[54];
};
```

这里 `cards_` 是 54 个指针组成的普通数组，并不是 54 个 `Card` 对象组成的数组；每张 `Card` 通过 `new Card(i)` 单独构造，因此可以传入 `id`。

但这也立刻带来新的责任：构造函数中有 54 次 `new`，析构函数中就必须有对应的 54 次 `delete`。这正是动态内存管理“灵活，但需要负责”的本质。

静态和栈区自动管理的优点是：不用担心普通局部对象的释放。动态内存管理的价值是：对象数量、大小、创建时间和销毁时间都能按程序运行时的需要决定。

### 单对象（变量）的动态分配及释放

单个对象或变量的动态分配使用 `new`，释放使用 `delete`：

```cpp
T* p = new T(参数列表);
delete p;
```

其中 `T` 可以是内置类型、自定义类类型，甚至是指针类型。

**`new` 的基本用法**：

```cpp
int* p1 = new int;      // int 未初始化，值不确定
int* p2 = new int(5);   // 值为 5
int* p3 = new int();    // 值初始化为 0

A* p4 = new A;          // 调用 A 的无参构造函数
A* p5 = new A(100, 200); // 调用匹配的有参构造函数
```

`new A(100, 200)` 中的参数会传给 `A` 的构造函数。对类对象来说，`new` 不是只申请一块字节空间，而是“申请空间 + 调用构造函数”。

动态创建的对象本身通常没有普通变量名：

```cpp
A* p = new A(10);
```

真正创建出来的是一个位于动态存储区的 `A` 对象；程序只能通过 `p` 保存的地址访问它：

```cpp
p->func();
```

如果 `p` 的地址被覆盖或离开可访问范围，且没有其他指针保存该对象地址，这个对象就失去了释放入口，形成**内存泄漏**。

**`delete` 的基本用法**：

```cpp
delete p;
```

对单个类对象，`delete` 的过程可以粗略理解为：

1. 若 `p` 是空指针，什么也不做。
2. 调用 `p` 所指对象的析构函数。
3. 释放这块对象存储空间。

因此：

```cpp
A* p = new A(10);
delete p;
```

对应的生命周期是：分配足够空间、调用 `A` 的构造函数、正常使用对象、调用 `A` 的析构函数、归还空间。

> `new` 是“分配空间 + 构造对象”；`delete` 是“析构对象 + 释放空间”。这正是它们与 `malloc/free` 最关键的区别。

`delete` 释放的是指针**指向的对象**，不会自动修改指针变量自身：

```cpp
A* p = new A;
delete p;

// p 还保存着旧地址，但该地址已经不能再作为有效 A 对象访问
```

此时 `p` 是**悬空指针**。如果该指针后续还会被使用，常见防御性写法是：

```cpp
delete p;
p = nullptr;
```

这样再次写 `delete p;` 也是安全的，因为 `delete nullptr;` 什么也不做；但要注意，把一个指针置空并不能消除其他别名指针的悬空问题。

**`new` 与 `delete` 必须配对。**

```cpp
A* p = new A;
delete p;
```

单对象用 `new` 创建，就用普通 `delete` 释放。数组则必须使用 `new[]` 和 `delete[]`，后面会单独说明。

```cpp
A* array = new A[50];
delete[] array;
```

以下混用属于未定义行为：

```cpp
A* p1 = new A;
delete[] p1; // 错误

A* p2 = new A[50];
delete p2;  // 错误
```

**`new` 的底层过程**：

```cpp
T* p = new T(1, 2);
```

可粗略理解为：

1. 调用合适的 `operator new` 申请能容纳 `T` 的原始内存。
2. 若申请失败，普通 `new` 通常抛出 `std::bad_alloc`；也可能先调用已设置的 `new_handler`。
3. 在成功申请的地址上调用 `T` 的构造函数。
4. 把原始地址作为 `T*` 返回。

若希望在普通 `new` 连续分配失败时先执行自定义处理逻辑，可以设置 `new_handler`：

```cpp
#include <new>

void onAllocationFailure() {
    // 尝试释放可回收资源、记录日志，或直接抛出异常
    throw std::bad_alloc();
}

int main() {
    std::new_handler old = std::set_new_handler(onAllocationFailure);

    // 此处的普通 new 若无法分配，可能调用 onAllocationFailure

    std::set_new_handler(old); // 恢复原处理函数
}
```

`new_handler` 主要用于理解“分配失败时的处理入口”。一般业务代码更常见的做法是让 `std::bad_alloc` 向上传播，或避免进行不受控的大规模手动分配。

对应的伪代码可以理解为：

```cpp
void* raw = ::operator new(sizeof(T));
T* p = new (raw) T(1, 2); // 在 raw 指向的内存上构造 T
```

上面只是帮助理解 `new` 的两个阶段。平时不能把普通 `new` 改写成这样后忘记异常处理和配对释放；普通的 `new T(...)` 更安全、更常用。

**`delete` 的底层过程**：

```cpp
delete p;
```

可以粗略理解为：

```cpp
if (p != nullptr) {
    p->~T();
    ::operator delete(p);
}
```

实际中编译器会按类型和可见的分配/释放函数选择合适的版本。重点不是死记伪代码，而是记住：析构和释放内存是两个连续但不同的动作。

**`new/delete` 与 `malloc/free`**：

| 对比点       | `new/delete`             | `malloc/free`                      |
| ------------ | ------------------------ | ---------------------------------- |
| 来源         | C++ 语言语法             | C 标准库函数                       |
| 类型信息     | 知道目标类型             | 只按字节数处理                     |
| 构造和析构   | 会调用构造函数、析构函数 | 不会自动调用                       |
| 返回类型     | 对应类型的指针           | `void*`                            |
| C++ 对象管理 | 常规选择                 | 不适合直接管理有构造析构语义的对象 |

同一块内存的分配和释放方式也不能混用：`new` 得到的内存应由 `delete`（或 `delete[]`）释放；`malloc` 得到的内存应由 `free` 释放。不要对 `new` 得到的对象调用 `free`，也不要对 `malloc` 得到的地址调用 `delete`。

现代 C++ 中，若确实需要动态分配，通常还应优先考虑智能指针或标准容器，而不是让裸指针长期承担所有权责任。

### 重载 operator new 和 operator delete

`new` 和 `delete` 是完整表达式；真正负责“原始内存申请”和“原始内存释放”的函数分别是 `operator new` 和 `operator delete`。

```cpp
A* p = new A(9);
delete p;
```

可以把它分成四个角色：

| 机制              | 负责内容                     |
| ----------------- | ---------------------------- |
| `operator new`    | 申请尚未构造成对象的原始内存 |
| 构造函数          | 把原始内存初始化为有效对象   |
| 析构函数          | 清理对象拥有的资源           |
| `operator delete` | 归还原始内存                 |

重载 `operator new/operator delete` 定制的是第一步和最后一步，**不会替代构造函数或析构函数**。

**类专属 `operator new` 的基本形式**：

```cpp
#include <cstddef>

class A {
public:
    static void* operator new(std::size_t size);
    static void operator delete(void* p) noexcept;
};
```

`operator new` 返回 `void*`，因为它返回的是尚未构造成 `A` 对象的原始内存地址。第一个参数通常是 `std::size_t size`，表示需要多少字节。

```cpp
A* p = new A;
```

对这个表达式，编译器会把 `sizeof(A)` 作为大小传给合适的分配函数。

类中的 `operator new` 和 `operator delete` 本质上是静态成员函数：对象尚未构造时没有可用的 `this` 指针；对象已经析构后也不能依赖 `this`。即使声明时不写 `static`，它们也不属于某个具体对象。

**类专属版本与全局版本**：若类中提供了自己的版本，创建该类对象时会优先考虑类中的版本；若没有，则使用全局版本。

```cpp
class A {
public:
    static void* operator new(std::size_t size) {
        return ::operator new(size);
    }

    static void operator delete(void* p) noexcept {
        ::operator delete(p);
    }
};
```

前面的 `::` 很重要：`::operator new` 和 `::operator delete` 表示全局版本。若在 `A::operator new` 内部再次写不带作用域的 `operator new(size)`，就可能递归调用 `A::operator new` 自己。

**计数示例**：类专属分配函数可用于记录该类在动态区的分配次数。

```cpp
#include <cstddef>

class A {
public:
    static void* operator new(std::size_t size) {
        void* p = ::operator new(size);
        ++allocation_count_;
        return p;
    }

    static void operator delete(void* p) noexcept {
        ++deallocation_count_;
        ::operator delete(p);
    }

    static int allocationCount() {
        return allocation_count_;
    }

    static int deallocationCount() {
        return deallocation_count_;
    }

private:
    static int allocation_count_;
    static int deallocation_count_;
};

int A::allocation_count_ = 0;
int A::deallocation_count_ = 0;
```

这样可以帮助调试“分配次数和释放次数是否明显不匹配”。但它只能统计经由该类专属 `operator new/delete` 的分配，不能替代专业的内存检测工具。

**带额外参数的 `operator new`**：分配函数还可以有额外参数，例如给分配操作打调试标签：

```cpp
class A {
public:
    static void* operator new(std::size_t size, const char* tag);
};

A* p = new ("debug") A(8);
```

这里 `"debug"` 用于匹配 `operator new` 的额外参数。它表示“如何申请原始内存”的扩展形式，构造函数参数仍然是 `A(8)` 中的 `8`，两者不能混淆。

在实际工程中，带额外参数的分配函数常用于内存池、文件行号追踪、分配日志等场景。若构造函数在这种分配后抛出异常，还需要提供能匹配额外参数的释放函数，以便清理已经申请的原始内存；这一点属于更进阶的异常安全问题。

**`operator delete` 的形式**：常见的非数组释放形式是：

```cpp
static void operator delete(void* p) noexcept;
```

也可提供带大小参数的形式：

```cpp
static void operator delete(void* p, std::size_t size) noexcept;
```

实际 `delete` 表达式会依据可见的函数版本和语言规则选择合适的释放函数。复习时要抓住核心：`operator delete` 负责释放原始内存，不负责替代析构函数。

### 数组的动态分配及释放

数组的动态分配使用 `new[]`，释放必须使用 `delete[]`：

```cpp
T* p = new T[n];
delete[] p;
```

`n` 可以是运行时才确定的变量：

```cpp
int n;
std::cin >> n;

T* p = new T[n];
// 使用 p[0] 到 p[n - 1]
delete[] p;
```

`new T[n]` 可以理解为：

1. 分配能容纳 `n` 个 `T` 对象的连续原始内存。
2. 依次构造这 `n` 个元素。
3. 返回第一个元素的地址。

如果 `T` 是类类型：

```cpp
A* array = new A[50];
```

通常会调用 50 次 `A` 的无参构造函数。因此：

```cpp
class A {
public:
    A(int value);
};

A* array = new A[50]; // 错误：没有 A()
```

若类没有无参构造函数，就不能直接用这种方式创建对象数组。可以改用指针数组逐个构造，或使用能在运行期逐个 `emplace` 的容器。

对于内置类型，初始化方式也有差别：

```cpp
int* a = new int[10];   // 元素未初始化，值不确定
int* b = new int[10](); // 值初始化，元素为 0
```

**`delete[]` 的语义**：

```cpp
delete[] p;
```

可以理解为：

1. 若 `p` 为 `nullptr`，什么也不做。
2. 依次调用数组中每个元素的析构函数。
3. 释放整个数组的原始内存。

这就是为什么动态数组必须使用 `delete[]`：它需要知道这是一个数组，并按数组方式析构所有元素。

```cpp
A* p = new A[50];
delete[] p; // 正确：析构 50 个 A 对象
```

不能写成：

```cpp
delete p; // 错误：new[] 与 delete 不匹配
```

`delete[]` 不需要程序员再次写元素个数。具体实现会保存或推导释放数组所需的信息；程序员只需保持 `new[]` 与 `delete[]` 的正确配对。

**数组版本的分配函数**：单对象与数组会使用不同的分配/释放函数。

| 创建与释放表达式          | 对应的分配/释放函数                    |
| ------------------------- | -------------------------------------- |
| `new T` / `delete p`      | `operator new` / `operator delete`     |
| `new T[n]` / `delete[] p` | `operator new[]` / `operator delete[]` |

若类需要为数组定制底层分配策略，可提供：

```cpp
static void* operator new[](std::size_t size);
static void operator delete[](void* p) noexcept;
```

**动态指针数组**：若 `Card` 没有无参构造函数，并且牌数还由运行时决定，可以这样处理：

```cpp
class Poker {
public:
    Poker(int deck_count)
        : count_(54 * deck_count),
          cards_(new Card*[count_]) {
        for (int i = 0; i < count_; ++i) {
            cards_[i] = new Card(i % 54);
        }
    }

    ~Poker() {
        for (int i = 0; i < count_; ++i) {
            delete cards_[i];
        }
        delete[] cards_;
    }

private:
    int count_;
    Card** cards_;
};
```

这里有两层动态资源：每个 `cards_[i]` 指向一个单独创建的 `Card`，而 `cards_` 自己还指向一块动态分配的指针数组。因此析构时也有两步：先逐个 `delete cards_[i]`，再 `delete[] cards_`。

这个例子说明了手动动态内存的复杂性：资源层级一多，构造失败、拷贝构造、赋值、自我赋值、异常路径都需要额外设计。实际工程中，更推荐让 `std::vector`、`std::unique_ptr` 等 RAII 类型承担这些责任。

### 智能指针和共享指针

裸指针的典型写法是：

```cpp
T* p = new T;
p->f();
delete p;
```

问题不在于这三行本身，而在于真实程序中 `new` 与 `delete` 往往隔着很长逻辑，还可能夹着提前 `return`、异常或多个分支。只要有任意一条路径忘记执行 `delete`，就会内存泄漏。

**智能指针**的基本思想是：让一个局部对象保存堆对象地址，并在这个局部对象析构时自动释放被托管资源。

```text
局部智能指针对象离开作用域
            ↓
调用智能指针析构函数
            ↓
释放其拥有的堆对象
```

这正是 **RAII**（Resource Acquisition Is Initialization，资源获取即初始化）思想：资源的获得与对象构造绑定，资源的释放与对象析构绑定。

课程中可以用一个极简的独占智能指针理解原理：

```cpp
template <typename T>
class SimplePtr {
public:
    explicit SimplePtr(T* p) : ptr_(p) {}

    ~SimplePtr() {
        delete ptr_;
    }

    T* operator->() {
        return ptr_;
    }

    T& operator*() {
        return *ptr_;
    }

    SimplePtr(const SimplePtr&) = delete;
    SimplePtr& operator=(const SimplePtr&) = delete;

private:
    T* ptr_;
};
```

使用时：

```cpp
void f() {
    SimplePtr<T> ptr(new T);

    ptr->method();
    (*ptr).method();
} // 离开作用域，SimplePtr 析构，自动 delete 内部的 T 对象
```

`ptr->method()` 能成立，是因为智能指针重载了 `operator->`；`(*ptr).method()` 能成立，是因为它重载了 `operator*`。这里 `(*ptr)` 必须有括号，因为成员访问运算符 `.` 的优先级高于一元解引用 `*`。

上面的 `SimplePtr` 只是为了理解 RAII。它有一个关键语义：**独占所有权**。两个 `SimplePtr` 不能同时以“都负责 `delete`”的身份管理同一裸指针，因此复制被显式禁止。

历史上的 `std::auto_ptr` 曾尝试通过“拷贝时转移所有权”来解决复制问题，但这种语义太反直觉，已经在 C++17 被移除。现代 C++ 常用的智能指针包括：

| 类型                 | 所有权语义                 | 常见用途                       |
| -------------------- | -------------------------- | ------------------------------ |
| `std::unique_ptr<T>` | 独占，不可拷贝、可移动     | 默认优先选择的动态对象所有者   |
| `std::shared_ptr<T>` | 多个所有者共享，引用计数   | 确实需要共享生命周期时         |
| `std::weak_ptr<T>`   | 不拥有资源，只观察共享对象 | 解决共享指针循环引用、临时观察 |

例如独占资源通常写成：

```cpp
#include <memory>

auto ptr = std::make_unique<T>();
ptr->f();
```

不需要手写 `delete`；`ptr` 离开作用域后会自动销毁它拥有的 `T` 对象。

当多个对象确实需要共同延长同一资源的生命周期时，才使用共享指针：

```cpp
#include <memory>

std::shared_ptr<T> ptr = std::make_shared<T>();
ptr->f();
```

共享并不天然比独占更“高级”。共享所有权会增加引用计数、循环引用和生命周期判断的复杂度；若资源只有一个明确拥有者，应优先使用 `unique_ptr` 或普通成员对象。

### 共享指针的实现（一）

共享指针要解决的问题是：多个对象可以指向同一个堆区资源，但只有最后一个使用者离开时才真正释放资源。

如果多个对象直接复制同一个裸指针：

```text
b1.pa_ ──┐
         ├── A 对象
b2.pa_ ──┘
```

而析构函数都直接写：

```cpp
delete pa_;
```

那么先析构的对象会释放 `A`，后析构的对象会再次 `delete` 同一地址，造成重复释放。解决方法是引入**引用计数**。

第一种实现把引用计数直接放进被共享对象 `A` 内部：

```cpp
class A {
public:
    A(int data = 0) : data_(data), use_count_(1) {}

    void addRef() {
        ++use_count_;
    }

    int releaseRef() {
        return --use_count_;
    }

private:
    int data_;
    int use_count_;
};
```

`use_count_` 表示当前有多少个管理对象共享这个 `A`。首次 `new A` 后，只有一个拥有者，因此计数从 `1` 开始。

管理类 `B` 可以写成：

```cpp
class B {
public:
    B(int value = 0) : pa_(new A(value)) {}

    B(const B& rhs) : pa_(rhs.pa_) {
        pa_->addRef();
    }

    B& operator=(const B& rhs) {
        if (this != &rhs) {
            release();
            pa_ = rhs.pa_;
            pa_->addRef();
        }
        return *this;
    }

    ~B() {
        release();
    }

private:
    void release() {
        if (pa_->releaseRef() == 0) {
            delete pa_;
        }
    }

private:
    A* pa_;
};
```

构造过程可以这样理解：

```cpp
B b1(8);  // 新建 A(8)，use_count_ = 1
B b2(b1); // b2.pa_ 指向同一个 A(8)，use_count_ = 2
B b3(10); // 新建另一份 A(10)，其 use_count_ = 1
```

内存关系为：

```text
b1.pa_ ──┐
         ├── A(8), use_count_ = 2
b2.pa_ ──┘

b3.pa_ ─────> A(10), use_count_ = 1
```

若局部对象按 `b3 → b2 → b1` 的顺序析构：

1. `b3` 析构，`A(10)` 的计数从 1 减到 0，因此删除 `A(10)`。
2. `b2` 析构，`A(8)` 的计数从 2 减到 1，仍有人使用，不删除。
3. `b1` 析构，`A(8)` 的计数从 1 减到 0，删除 `A(8)`。

拷贝构造的核心不再是深拷贝：

```cpp
pa_ = rhs.pa_;
pa_->addRef();
```

它复制的是地址并增加计数，表示共享同一份资源。析构的核心也不再是无条件 `delete`，而是“先减计数，减到 0 才 delete”。

这种方式的缺点是：被共享类 `A` 必须专门加入 `use_count_`、`addRef`、`releaseRef` 等资源管理逻辑。若 `A` 来自第三方库，或它只是一个纯业务类，不希望被引用计数污染，这种方案就不够通用。

这种“把计数嵌入资源对象”的做法通常称为**侵入式引用计数**。它能说明原理，但标准库 `shared_ptr` 并不要求被管理对象自己提供计数字段。

### 共享指针的实现（二）

第二种思路是不修改被共享类 `A`，而把引用计数独立出来。课件中常用一个 `int*` 指向堆区计数：

```cpp
class B {
private:
    A* pa_;
    int* use_;
};
```

其中：

- `pa_` 指向实际被共享的 `A` 对象；
- `use_` 指向“这组共享者共同拥有的引用计数”。

为什么不能直接把计数写成普通 `int` 成员：

```cpp
class B {
private:
    A* pa_;
    int use_;
};
```

因为每个 `B` 对象都会有自己的一份 `use_`。`b1` 和 `b2` 即使指向同一个 `A`，它们的计数也彼此独立，无法代表“同一资源现在被两个人共享”。

为什么也不能写成静态成员：

```cpp
class B {
private:
    A* pa_;
    static int use_;
};
```

静态成员只有一份，所有 `B` 对象都会共用。这样 `b1/b2` 共享 `A(8)` 的计数，与 `b3` 独占 `A(10)` 的计数会混在一起，粒度又太粗。

正确的关键是：**共享同一个 `A` 的那一组 `B`，也要共享同一个计数对象；不同 `A` 对应不同计数对象。**

一个简化实现如下：

```cpp
class B {
public:
    B(int value = 0)
        : pa_(new A(value)),
          use_(new int(1)) {}

    B(const B& rhs)
        : pa_(rhs.pa_),
          use_(rhs.use_) {
        addRef();
    }

    B& operator=(const B& rhs) {
        if (this != &rhs) {
            releaseRef();
            pa_ = rhs.pa_;
            use_ = rhs.use_;
            addRef();
        }
        return *this;
    }

    ~B() {
        releaseRef();
    }

    A* operator->() const {
        return pa_;
    }

private:
    void addRef() {
        ++(*use_);
    }

    void releaseRef() {
        if (--(*use_) == 0) {
            delete pa_;
            delete use_;
        }
    }

private:
    A* pa_;
    int* use_;
};
```

各个成员函数的职责如下：

| 操作     | `pa_` 的处理                     | `use_` 的处理             |
| -------- | -------------------------------- | ------------------------- |
| 普通构造 | 新建 `A`                         | 新建计数，初值为 1        |
| 拷贝构造 | 复制地址，共享同一 `A`           | 复制计数地址，再加 1      |
| 析构     | 最后一个使用者才删除 `A`         | 先减 1，减到 0 时删除计数 |
| 赋值     | 先放弃旧共享关系，再加入右侧关系 | 先减旧计数，再加新计数    |

赋值函数必须处理自我赋值：

```cpp
if (this != &rhs) {
    // 先放弃当前资源，再共享 rhs 的资源
}
```

若没有这项判断，`b = b;` 会先把当前资源的计数减掉；当它原本是最后一个使用者时，资源可能已经被释放，随后又试图从同一个 `rhs` 读取失效指针。

两种引用计数实现对比如下：

| 实现方式 | 计数存放位置        | 优点                     | 缺点                             |
| -------- | ------------------- | ------------------------ | -------------------------------- |
| 方法一   | 被共享对象 `A` 内部 | 直观、代码较少           | 必须修改 `A`，资源管理侵入业务类 |
| 方法二   | 独立的堆区计数对象  | 不必修改 `A`，通用性更好 | 需要同时管理资源地址和计数地址   |

真实的 `std::shared_ptr` 使用更完整的**控制块**保存引用计数、删除器等信息，而不是只裸放一个 `int*`。并且在多线程环境中，引用计数的增减还要考虑原子操作。课件中的两种写法用于理解基本生命周期，不应直接当作生产级共享指针实现。

### 其它说明

**不要对 `void*` 直接使用 `delete`。**

```cpp
A* p = new A;
void* q = p;

delete q; // 错误：不能据此正确确定 A 的析构语义
```

`void*` 只表示“某个地址”，不携带对象的静态类型。删除类对象时，编译器需要知道应调用哪个析构函数；把 `A*` 转成 `void*` 后再删除，会丢失这层类型信息。此类写法通常会得到编译器警告，行为也不应依赖。

一般来说，`delete` 后面的指针类型必须与动态对象类型匹配，或是具有虚析构函数的多态基类指针。例如：

```cpp
class Base {
public:
    virtual ~Base() = default;
};

class Derived : public Base {
};

Base* p = new Derived;
delete p; // 正确：虚析构保证 Derived 也会被正确析构
```

若基类析构函数不是虚函数，却通过 `Base*` 删除 `Derived` 对象，也会造成未定义行为。

**悬空指针与内存泄漏的区别**：

```cpp
A* p = new A;
delete p;
p->f(); // 悬空指针：对象已经释放，却继续访问旧地址
```

这是“对象已经没了，指针还在用”的问题。

```cpp
A* p = new A;
return; // 内存泄漏：对象还在，但再也没有释放入口
```

这是“对象还占着内存，却没人再能释放它”的问题。两者方向相反，但都源于手动资源管理不可靠。

**写时复制**（Copy On Write，COW）建立在共享与引用计数之上。多个对象读取同一资源时可以共享；但一旦其中一个要修改，就不能直接改共享对象，否则其他使用者也会看到变化。

写时复制的基本策略是：

1. 读取时，多个对象共享同一资源。
2. 写入前检查引用计数。
3. 若计数为 1，当前对象独占资源，可以直接修改。
4. 若计数大于 1，当前对象先复制出一份独立资源，再修改自己的副本。

示意代码如下。这里先把新资源和新计数准备好，再退出旧共享关系；这样分配失败时，当前对象仍保持原来的共享状态：

```cpp
#include <memory>

void B::writeA(int value) {
    if (*use_ > 1) {
        auto new_pa = std::make_unique<A>(*pa_);
        auto new_use = std::make_unique<int>(1);

        --(*use_);              // 当前对象退出旧共享关系
        pa_ = new_pa.release(); // 当前对象持有新资源
        use_ = new_use.release();
    }

    pa_->setData(value);
}
```

这就是“读时共享，写时复制”。它能减少只读场景中的重复拷贝，但实现需要谨慎处理异常安全、线程安全和所有可能的写入口。现代 C++ 中，写时复制并不是所有共享数据结构的默认选择，理解其思想比盲目套用更重要。

**定位分配**（placement new）是在一块已经存在的内存上构造对象，而不是再次向系统申请内存。

普通 `new`：

```cpp
A* p = new A(1);
```

包含两件事：申请内存，并在其中构造 `A`。

定位分配：

```cpp
#include <cstddef>
#include <new>

alignas(A) std::byte storage[sizeof(A) * 3];

A* p1 = ::new (static_cast<void*>(storage)) A(1);
A* p2 = ::new (static_cast<void*>(storage + sizeof(A))) A(2);
A* p3 = ::new (static_cast<void*>(storage + sizeof(A) * 2)) A(3);
```

这里 `storage` 是已经存在的原始存储空间。`::new (地址) A(...)` 不会再申请空间，只会在指定地址上调用构造函数。

`alignas(A)` 很重要：原始缓冲区不仅要有足够的字节数，还必须满足 `A` 的对齐要求。课件中常见的 `char data[...]` 写法用于说明思想；在实际代码中应保证对齐。

定位分配得到的对象不能直接用普通 `delete`：

```cpp
delete p1; // 错误：p1 的存储不是由普通 new A 得到的
```

因为普通 `delete` 会尝试归还一块它并未申请的内存。应当在对象不再需要时显式调用析构函数，并由原始缓冲区的所有者负责回收缓冲区：

```cpp
p3->~A();
p2->~A();
p1->~A();
```

上例的缓冲区是局部数组，离开作用域后它的原始存储自动结束；显式析构仍然必要，因为“缓冲区消失”不等于“其中构造过的对象已经正确执行析构逻辑”。

定位分配常用于内存池、对象池、容器实现和对性能敏感的底层组件。它很强大，但要求程序员同时正确管理：原始内存来源、对象构造位置、对象析构顺序和缓冲区最终回收。因此在一般业务代码中，优先选择标准容器和 RAII 类型通常更稳妥。
